# Solva app · Tauri 2 plan (Next 1)

Goal: one codebase → GitHub Pages demo (unchanged) + Windows .msi/.exe + Android .apk with
encrypted local storage and encrypted sync to the user's own cloud drive.

## 1. Repo layout (web files stay at the root)

```
index.html, *.js, *.css, assets/      ← unchanged; Pages keeps deploying them as today
store.js                              ← NEW: the one save/load API every screen calls
store-web.js                          ← NEW: web/demo backend (memory + demo seeds)
store-native.js                       ← NEW: app backend (calls Rust through invoke)
package.json                          ← NEW: only @tauri-apps/cli (dev), scripts tauri:dev / tauri:build
tools/build_web.mjs                   ← NEW: copies the web files into dist/ (same list as pages.yml)
src-tauri/
  tauri.conf.json                     ← frontendDist "../dist", devUrl http://localhost:5174, withGlobalTauri
  Cargo.toml, build.rs, capabilities/default.json
  src/lib.rs                          ← commands: vault_*, rec_*, doc_*, sync_*
  src/vault.rs                        ← key handling (DEK, wrap/unwrap, passphrase)
  src/crypt.rs                        ← AES-256-GCM seal/open, Argon2id
  src/disk.rs                         ← encrypted files under the app data dir
  src/sync/{mod,gdrive,onedrive}.rs   ← cloud backends behind one trait
  src/hello_win.rs                    ← Windows Hello key (windows crate)
  gen/android/…                       ← generated by `tauri android init`
  plugins/keystore/ (Kotlin)          ← Android Keystore + BiometricPrompt CryptoObject
.github/workflows/app.yml             ← NEW: Windows + Android builds → CI artifacts
```

- No bundler. `withGlobalTauri: true` exposes `window.__TAURI__.core.invoke` to plain scripts.
- `pages.yml` copies an explicit list (`index.html *.js *.css assets`), so `src-tauri/`, `docs/`,
  `package.json` never reach Pages. Add `store*.js` to nothing: `*.js` already covers them.
- `build_web.mjs` reuses the `?v=` stamp idea (commit or package version) so the app never
  serves stale files after an update.
- Inline boot script (index.html:19) moves to a file or gets a CSP hash (Tauri sets a CSP).

## 3. Store API (screens call only this)

```js
Store.ready()                       // resolves when unlocked (web: at once)
Store.get(col, id) / Store.all(col) // → objects (Dates revived)
Store.put(col, obj) / Store.del(col, id)
Store.doc.add(meta, bytes) → id     // bank statements, invoices, PBC docs
Store.doc.open(id) → Blob           // decrypted in memory, never written plain
Store.doc.list(filter)
Store.on('change', fn)              // sync pulled new data → re-render
Store.lock() / Store.status()       // 'locked' | 'open' | 'syncing' | 'offline'
```
Collections: `eng`, `time`, `invoices`, `pbc`, `ye`, `memory` (Autopilot), `desk` (settings,
setLog, sign-offs), `clients`, `deadlines`. Each record carries
`{ id, rev, at (hybrid clock), dev (device id), del? }`.

Done (step 2): `store.js` (API + web backend) and `store-bind.js` (state ↔ records). Instead of a
`Store.put` at each of ~40 mutation points, `render()` ends with `Bind.flush()`, which diffs each bound
record against what was last saved and puts/deletes only what changed (undo included). Bound now:
eng, time, invoices, pbc, aje, chase, mine (lists) + yeSign, memory, settings, setLog, who, filed,
checks (single records). Not bound yet: the Autopilot run/review state and CLIENTS (per-run demo state).

## 4. Keys and unlock (Next 3)

Done (step 4 keys): `vault.rs` (DEK, Argon2id m=64 MB t=3 p=1 → `vault.json`; HKDF device wrap → `vault.local.json`;
step 3 dev key adopted as the DEK in debug), `device.rs` (hello | file test key | none), `hello_win.rs`
(KeyCredentialManager sign → secret, raises the Hello dialog). Commands `vault_status/create/unlock/lock`;
`StoreNative.vault.*`; the store loads only once the vault is open. Passphrase min 10 chars. Interim JS prompts stand in
for the lock/onboarding screens. Passphrase unlock on a device with no wrap re-wraps for it (cancel = still unlocks).

- **DEK**: one random 256-bit data key per vault. Every record and document = AES-256-GCM,
  random 96-bit nonce, AAD = `col/id/rev`. Lives only in Rust memory (zeroized on lock).
- **Device wrap**: the DEK is stored only wrapped by a device key:
  - Windows: Windows Hello `KeyCredentialManager` RSA key signs a fixed challenge
    (PKCS#1 v1.5 is deterministic) → HKDF → wrap key. Fingerprint/face/PIN unlocks.
  - Android: Keystore AES key with `setUserAuthenticationRequired(true)`, unwrap through
    `BiometricPrompt` + `CryptoObject` (fingerprint or device PIN). Small Kotlin plugin;
    the stock `tauri-plugin-biometric` only says yes/no, it does not hold keys.
- **Passphrase wrap**: Argon2id(passphrase, salt, ~64 MB, 3 passes) → second wrap of the same
  DEK, stored as `vault.json` in the cloud folder. Adding a device = sign in to the drive →
  download `vault.json` → passphrase → DEK → re-wrap with the new device key.
- Passphrase is also the recovery path if a device is lost. No passphrase + no device = data
  gone (by design; say so in the setup screen).
- Auto-lock after N min idle and when the app goes to the background (Android).

## 5. Disk format (Next 2)

App data dir (`%APPDATA%\ca.solva.app`, Android internal storage):
```
vault.local.json            device-wrapped DEK, device id, settings
rec/<col>/<id>.enc          one sealed JSON per record
doc/<id>.enc + doc/<id>.m   sealed bytes + sealed meta (name, type, client, size, sha256)
sync/state.json             sealed: last cursor per backend, pending uploads
```
Ids are random, so neither disk nor cloud file names reveal client names.

## 6. Sync (Next 4)

- Cloud sees only `.enc` files + `vault.json` (wrapped DEK) in an app-only folder:
  Google Drive `appDataFolder` (scope `drive.appdata`) or OneDrive App Folder
  (`Files.ReadWrite.AppFolder`). Neither can see the user's other files.
- OAuth PKCE: Windows = loopback redirect; Android = deep link (`tauri-plugin-deep-link`).
  Refresh token sealed with the DEK.
- Loop: push local changes since last sync → list remote changes since cursor → for each
  record keep the higher `(at, dev)`; the loser is kept in `rec/_conflicts/` and listed on a
  "Conflicts" panel. Documents are write-once: same id + different hash → keep both
  ("… (copie Appareil B)").
- Deletes are tombstones (`del: true`) kept 90 days.
- Runs on unlock, every 5 min while open, and on "Sync now". Offline = queue.

## 7. Builds and CI (Next 5)

- `app.yml` on tag `app-v*` + manual: `windows-latest` → `tauri build` → .msi + NSIS .exe;
  `ubuntu-latest` + JDK 17 + Android SDK/NDK + Rust Android targets → `tauri android build`
  → .apk. Uploaded as workflow artifacts. Unsigned until signing is decided.
- Local toolchain (none installed yet): rustup (MSVC), VS 2022 Build Tools "C++ desktop",
  WebView2 (built into Windows 11); Android: Android Studio (SDK + NDK), JDK 17,
  `rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android`.
  CI can build both, so local Android tools are only needed to debug on a phone.

## 8. Order of work

1. Scaffold: package.json, build_web.mjs, src-tauri (empty commands), app opens the demo. 
2. `store.js` + web backend; move screens onto it; Pages demo behaves exactly as now.
3. Rust disk + crypt + native backend with a dev-only fixed key; data survives restart.
4. Vault: Windows Hello, passphrase, lock screen. Then Android Keystore plugin.
5. Sync backend #1, conflicts panel; then backend #2.
